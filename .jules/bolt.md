## 2026-10-25 - Redundant API Calls in Dashboard Initialization
**Learning:** In `DashboardComponent`, `loadLancamentos` and `loadResumoMes` both independently call `contaService.getContasByMesReferencia(mesRef)`. During initialization (in the `effect`), they are called back-to-back synchronously. The cache in `ContaService` only caches resolved results. Thus, two identical Firestore queries are dispatched simultaneously because the first hasn't finished resolving to populate the cache before the second runs.

**Action:** We can optimize this by implementing a Promise-based cache or request coalescing in `ContaService`. This way, if a second request for the same `mesReferencia` comes in while the first is still in flight, it will return the same Promise, saving a redundant Firestore query.

## 2026-10-28 - Date Object Instantiation inside Angular Template Loops
**Learning:** In `DashboardComponent`, the `getRowClass(item)` method was called on every iteration of a table loop during Angular's change detection cycles. This method invoked `calcularDiffDataVencimento`, which instantiated a new `Date` object for the current day (`new Date()`) and reset its time (`hoje.setHours(0, 0, 0, 0)`) for every row.
**Action:** Avoid expensive operations like parsing or generating new `Date` instances in pure computational template methods. Memoize invariant calculations, like the timestamp representing 'today at midnight', using caching variables in the respective service. This limits the instantiation count to one per session-day rather than 'number-of-items multiplied by change-detection-ticks', drastically reducing garbage collector overhead.
